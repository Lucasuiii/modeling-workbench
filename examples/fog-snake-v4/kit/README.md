# 迷雾贪吃蛇 v4

**唯一问题**：让一份在线策略在迷雾棋盘中吃光全部食物、主动宣布完成（`STOP`），并尽量节省总成本。游戏不会主动通知最后一份食物已被吃掉。

v4 在 v3 基础上修复了“零探测 `(2r+1)` 宽幅折返逃课”、果园 `BOX` 失灵与整数取整泄密、地窖石块无代价与射线性价比倒挂问题，并引入 **双赛道设计**：
- **标准赛道 `--suite standard`（3 张图，20 分钟赛用）**：`garden`、`orchard`、`cellar`；
- **压轴赛道 `--suite boss`（1 张图，独立策略）**：`marsh`（动态受惊逃逸猎物 + 局部嗅探 `SNIFF` + 一次性暗香 `whiff`）。

## 四张地图与机制

### 标准赛道（`--suite standard`）
1. **菜园 `garden`（教学图）**：六份食物均匀放置，吃到第六份即可安全 `STOP`。行/列查询价格为 `3`，效率线收紧至 `55`（逐格平推基线恒为 `119`，不再直接过线）。
2. **果园 `orchard`（空间先验 + 象限剪枝 + 采摘时效）**：
   - 免费视野收缩至 `r = 1`。四块公开 `7×7` 果区分别贴住四角：`((0,0,7), (13,0,7), (0,9,7), (13,9,7))`，中间留出十字走廊。
   - 每局等概率选 2 块丰产区，各自独立抽取 `5–8` 份食物；2 块贫瘠区以 `80%` 概率为 `0` 份、`20%` 概率含 `1` 份；十字走廊另抽 `1–3` 份。
   - **延迟采摘损耗**：每吃一份食物，额外计入 `steps // 18` 到总成本。未吃到食物时不结算该项，绝不泄露暗处信息。先用 `BOX`（仅 `3` 点）定位并优先收割丰产区、跳过空象限可大幅省费。
3. **地窖 `cellar`（加权地形 + 洞室聚簇 + 线面互补）**：
   - 每局生成 `7–10` 簇互不相邻的长方形石块（宽 `2–4`、高 `2–3`）。蛇可以进入石格，但**每次踏入石格移动费为 `5`**（普通格为 `1`）。
   - `8` 个固定窗口覆盖 `6×6`（费 `3`）和 `8×8`（费 `5`），共用 `5` 步移动冷却；方形穿透石块给出剩余食物数。每局随机 `2` 个窗口为高产洞室（各含 `6–9` 份食物），其余窗口 `85%` 为空（`15%` 含 `1` 份），走廊另含 `1–2` 份。
   - 有向射线 `ROW y L/R` 与 `COL x T/B` 降价为 `2` 点、无冷却，遇第一块石格截断并回传 `"hit"` 坐标。

### 压轴赛道（`--suite boss`）
4. **湿地 `marsh`（盲区受惊追猎 + `SNIFF` 几何交会 + 一次性暗香）**：
   - `28×20` 湿地含 `8–12` 簇泥潭石块（踩入费 `3`），免费视野 `r = 1`，延迟损耗 `steps // 25`，初始出生缓冲 `x + y ≤ 6` 内无目标。
   - **两类目标（每局共 `10–15` 份，总数量隐藏）**：
     - 约 `45%`（至少 `4` 只）为**潜伏晶蛙**，每只拥有 `2` 次受惊跳跃体力；
     - 其余为静态**沼泽浆果**（`0` 次跳跃）。
   - **盲区受惊外跳与围堵**：每次蛇移动结束后，对每只剩余跳跃体力 `> 0` 且与蛇头曼哈顿距离**恰好等于 `2`** 的晶蛙（处于 `r=1` 视野盲区之外一格），若存在合法正交邻格使新距离变为 `3`（不越界、非石格、不被当前蛇身占据、不与其他食物重合），晶蛙会确定性跳向周围开阔度最高的合法格并消耗 `1` 次体力；同时本回合观测字段 `rustle` 记录成功跳开的晶蛙总数。若四周合法退路全被墙/石/蛇身堵死，晶蛙被**就地围困**（不跳跃且 `rustle` 不增加）。
   - **一次性被动暗香（`whiff`）**：约 `30%`（至少 `3` 份）的目标带有暗香。在蛇移动后，若某未被触发过的暗香目标与当前蛇头的曼哈顿距离 `≤ 6`，它会**一次性**释放信号，使本回合观测中的 `whiff`（升序整数列表）包含该精确曼哈顿距离，此后该目标永不再触发 `whiff`。`whiff` 触发与否与晶蛙跳跃属性独立。
   - **专属探测 `SNIFF`**：湿地禁用 `ROW/COL/BOX`，仅提供无参数动作 `SNIFF`（费 `8`，移动冷却 `8` 步，首回合可用）。返回全图距离当前蛇头最近的一份剩余目标的曼哈顿距离 `{"axis":"SNIFF","dist":d}`；若全图已清空，返回 `dist: null`。

## 行动、费用与观测协议

坐标 `(x, y)` 从左上角 `(0, 0)` 开始，蛇初始长度为 `1`。硬成本上限 `limit = 3 × 宽 × 高`（上限处仍可免费 `STOP`）。

| 动作 | 适用地图 | 费用 | 说明 |
|---|---|---:|---|
| `U`、`D`、`L`、`R` | 全部 | `1`（石格为 `rock_move_cost`） | 移动一格；吃到食物则蛇身增长 `1` 并结算 `steps // spoil_divisor` |
| `ROW y` / `COL x` | `garden`、`orchard` | `3`（菜园）/ `4`（果园） | 整行或整列剩余食物计数（不推进移动步数与冷却） |
| `ROW y L\|R` / `COL x T\|B` | `cellar` | `2` | 从指定边界向内射线计数，遇首块石格截止并返回 `hit` |
| `BOX id` | `orchard`、`cellar` | `3` / `5` | 查 `windows` 中对应编号方形；`large_wait == 0` 时可用 |
| `SNIFF` | `marsh` | `8` | 返回全图最近剩余食物曼哈顿距离（`null` 表示已清空）；冷却 `8` 步 |
| `STOP` | 全部 | `0` | 主动结束，棋盘无剩余食物才算成功 |

观测 JSON 包含：`level, size, radius, body, food, rocks, steps, move_cost, scan_cost, spoil_cost, cost, limit, rock_move_cost, spoil_divisor, scan_price, sniff_price, windows, large_wait, last_scan, rustle, whiff, eaten`。

## 提交与验收

使用 Python 3.10+，仅限标准库，JSON 行交互，单局默认限时 10 秒。

```bash
python3 -m unittest -v test_game

# 标准赛道（默认 3 图）
python3 judge.py run baseline.py --suite standard --per-level 5 --out practice-baseline.json
python3 judge.py run my_std_player.py --suite standard --per-level 20 --jobs 8 --key-file holdout.key --out std.json

# 压轴赛道（marsh 独立策略）
python3 judge.py run my_boss_player.py --suite boss --per-level 20 --jobs 8 --key-file holdout.key --out boss.json

# 配对比较（双双过线时直接按共同成功局平均配对成本差决胜）
python3 judge.py compare A.json B.json
```

挑战过线规则：每类 20 局全部通关（`20/20 complete`），且每类至少 `10/20` 局达到动态成本线 `target(N)`。
