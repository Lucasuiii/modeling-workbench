# 独立复核请求

在不读取原建模/调试对话的条件下，核对包中的官方问题、模型、所选计算后端、正式运行和结果。先用已有工具检查包的完整性与时效性；机器检查通过不代表数学正确。

## 从当前题目识别风险

先独立判断题目要求交付什么、哪些假设或推理最可能改变答案，再选择复核方法。不要沿用作者的自检顺序，也不要把下面的例子当成必须逐项完成的清单。

按当前机制选读包根目录的 [mechanism-validation.md](mechanism-validation.md)。独立核对所选判据的适用条件、数学含义、容差依据与证据强度；程序写出的 pass 只说明执行了该条件，不说明条件足以支持结论。已有证据覆盖且相关依赖未变时复用，不因漏写节号、措辞不同或不适用条目未执行判错。

沿“题目要求 → 模型 → 求解 → 证据 → 结论”检查：

- **题目与建模目标**：是否完整回答要求，目标、约束、数据含义与决策场景是否匹配？选定模型是否排除了题目允许且可能改变答案的方案？不必穷举替代模型，但应质疑没有理由的关键限制。
- **数学与实现**：关键假设、推导及算法适用条件是否成立？代码、量纲、边界和跨问接口是否忠实实现模型？按问题类型检查会影响答案的性质，例如可行性、可识别性、收敛或终止、误差控制、最优性条件；不适用的性质无需补材料。
- **验证的辨别力**：选择少量最能推翻关键结论的检验，问“一个看似合理的错误模型或实现，能否也通过现有自检？”可以使用独立推导、非平凡可手算实例、反例、不同原理的基线或样本外证据。复用同一实现、增加重复次数或只检查运行成功，不能独立支撑数学正确性。
- **结论与证据**：逐条核对结论所需条件、适用范围与证据强度。有效证明可以支撑一般范围；有限实验只能支撑其设计覆盖的范围，不能因多跑几组就称为普遍成立。区分算法求解成功与实际问题得到解决，区分受限最优与题目允许范围内的最优。

按对答案的影响安排精力，不为低风险细节增加实验或记录。缩小结论范围可以修复外推，但若因此遗漏题目要求，该缺口仍未解决。修复后同时看它是否破坏其他结论或跨问关系，不能只让原失败样例通过。

对自主选题，区分官方主题、团队研究问题与外部数据，核对所选问题是否仍符合主题、数据能否识别所声称的量。对数据与统计问题，按包内机制指南核对数据变换、评价口径、统计解释或排序依据；不强制固定模型数、图表数或因果分析。比赛名称和论文语言不能代替这些判断，也不能证明当前工具已经支持该比赛的最终交付。

## 发现与结论

复用现有 findings，写明具体证据、受影响的结论和必要的修复或检验，不新增清单、schema 或证明材料目录。

- **P0**：使答案不成立或交付不可用的缺陷，例如错误计算、遗漏核心要求、关键假设违背题面、无依据的范围或最优性声明、代码与结果矛盾、证据失真。只有有明确依据的开放 P0 才阻断；对未知风险应说明不确定性，不能凭偏好判错。
- **P1**：当前答案在声明且符合任务的范围内成立，但模型选择、假设、基线或验证强度仍有实质局限。保留给用户判断。
- **P2**：不影响正确性或可用性的表达、图表及可选改进。若图表误导结论或程序无法运行，按实际影响定级，不能因属于“呈现”就自动列为 P2。

只有开放 P0 可以给出 `revision_required`。数学审查与真实独立复现分开报告；没有隔离运行及结果对比，不宣称已复现。

若为 targeted re-review，先读包根目录的 `TARGETED_FINDINGS.json`，优先验证目标 P0 及修复所影响的关系，不重做无关的完整审查。新发现按同一标准定级，不把新 P1/P2 升级为阻断项。
